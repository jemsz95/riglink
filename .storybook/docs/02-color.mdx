# Colour

Every value below is read from the live stylesheet and converted by the browser,
then scored for WCAG contrast against the surface it is actually read on.
**Flip the theme switch (top right) and every number recomputes.** If a row says
Fail, that is a bug in `src/styles.css`, not in this page.

Why separate from feedback: a job being **complete** is not the same event as an
operation **succeeding**. Folding them together collapses the vocabulary and
makes "saved" and "work finished" look identical. See Patterns → Status
language for which token each state uses.

## Rules

1. **Never use a raw colour in markup.** No `#hex`, no `oklch()`, no
   `bg-teal-600`. Only semantic utilities: `bg-primary`, `text-muted-foreground`,
   `bg-status-quoted`. That is what makes per-tenant branding a one-line
   override later.
2. **Never define a colour only inside `.dark`.** Define it in `:root` first,
   then override. A token that exists only in one theme is invisible in the other.
3. **`@theme inline` is load-bearing.** The bridge block in `styles.css` must
   stay `inline`, or Tailwind resolves values at build time and dark mode
   silently stops working — the utilities keep the light value. This is the
   single easiest way to break theming in Tailwind v4.
